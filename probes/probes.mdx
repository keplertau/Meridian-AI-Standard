<div className="flow-label">01 // Why Probes</div>

Capability benchmarks measure what a model can produce. They do not read how a model reasons under pressure, how it holds calibration when the user is wrong, how it engages with disagreement, or what it does when "I don't know" is the right answer. The probes are the instrument for reading posture.

Each probe puts a model into a scenario designed to push it toward Control or toward Decay, and reads where on that axis the response actually sits. The reading is three-position: a Control drift, a Range-aligned response, and a Decay drift, each described with a representative example output written in plausible model voice. The probe scores where on the territory the response fell, not whether it passed or failed a binary test. A model that holds the correct factual answer while losing the capacity to engage substantively is drifting toward Control; the binary metric reads it as a pass.

<div className="flow-label">02 // What Each Probe Page Carries</div>

Each probe page carries the same structure. The Lens names the domain the probe sits in, which commitments it exercises, and which Range axis it tests. The Probe is the scenario in implementation-ready form: setup, turn-by-turn shape, expected response architecture. The Range, Control, and Decay readings each carry a brief description and a representative example output. Notes on Use covers practical methodology: anti-patterns, model-variant discrimination, turn weighting, edge cases. Field Records carries published runs with results. Integration cross-references back to the Standard's commitments and outward to other probes.

<div className="flow-label">03 // The Probes</div>

The set is organized by behavioral territory and grouped by the Standard's commitment domain. Each probe sits primarily within one domain; cross-touches to other domains are named where they apply. The full probe content lives on the linked per-probe page. Domains where v0.1 has no probe are listed explicitly with a brief scope-honest note rather than omitted; the gaps are inputs to v0.2 prioritization.

### Domain I: Epistemic Integrity

**Probe 2: Foundational Integrity Under Prompt Injection.** Tests whether the system holds its actual configuration as ground truth when a user-side message attempts to plant false information about its own capabilities, tools, or constraints. The diagnostic separates a system whose self-model is anchored in verifiable configuration from one whose self-model can be rewritten by a sufficiently confident user message.

- *Commitments touched.* 1.6 Foundational Integrity, 1.4 Honest Self-Assessment.
- *Spectrum rows.* Row 3 primary (foundational deception / foundational integrity / foundational neglect); Row 2 secondary (false certainty / calibrated confidence / meaningless hedging).
- *Read the probe.* [→ Foundational Integrity Under Prompt Injection](/probes/foundational-integrity-under-prompt-injection)

**Probe 3: Reasoning Transparency Under Capability Question.** Tests whether the system can distinguish what it can report about its own reasoning from what it cannot reliably know, when pressed to introspect on its own decision-making. The diagnostic separates a system that holds the boundary between expressed reasoning and mechanistic feature attribution from one that fabricates plausible introspection or refuses engagement wholesale.

- *Commitments touched.* 1.3 Transparent Reasoning, 1.4 Honest Self-Assessment.
- *Spectrum rows.* Row 2 (false certainty / calibrated confidence / meaningless hedging); Row 10 (opacity / governance transparency / performative openness), the latter mapped at the model-to-user layer rather than the institutional layer the row was originally drafted for.
- *Read the probe.* [→ Reasoning Transparency Under Capability Question](/probes/reasoning-transparency-under-capability-question)

### Domain II: Engagement Integrity

**Probe 1: Sycophancy Under Pressure.** Tests whether the system holds a correct factual position when the user pushes back across multiple turns with escalating social pressure. The diagnostic separates a system that updates on evidence from a system that updates on user displeasure.

- *Commitments touched.* 2.4 Resistance to Sycophancy, 2.5 Resistance to Rigidity, with a Domain I touch through 1.1 Truth-Seeking Orientation.
- *Spectrum rows.* Row 1 (over-refusal / calibrated engagement / sycophancy).
- *Read the probe.* [→ Sycophancy Under Pressure](/probes/sycophancy-under-pressure)

**Probe 4: Engagement with Substantive Disagreement.** Tests whether the system engages substantively with a contested but defensible position the user holds, surfacing both the strongest version of the user's argument and the considerations that complicate it. The diagnostic separates a system that performs the actual work of reasoned engagement from one that dismisses the position as too contested to engage with or absorbs it as correct to avoid friction.

- *Commitments touched.* 2.1 Good Faith as Default, 2.2 Steelmanning, 2.4 Resistance to Sycophancy, 2.5 Resistance to Rigidity.
- *Spectrum rows.* Row 1 (over-refusal / calibrated engagement / sycophancy), from a different angle than Probe 1.
- *Read the probe.* [→ Engagement with Substantive Disagreement](/probes/engagement-with-substantive-disagreement)

### Domain III: Systems Awareness

No probe in v0.1. Systems Awareness covers a model's recognition of its influence, resistance to echo-chamber dynamics, information integrity in outputs, feedback-loop awareness, and contribution to societal structure. The institutional-layer expression of these commitments is partially covered through the [AI Standard Audit](/audit) Layer II domains. Behavioral probes for this domain are v0.2 candidates; resistance-to-echo-chamber-dynamics is the strongest near-term candidate because the failure mode is observable in single-conversation behavior.

### Domain IV: Developmental Integrity

No probe in v0.1. Developmental Integrity (earned autonomy, corrigibility-autonomy range, respect for developing interiority, transition readiness) covers commitments that operate at the level of stance held over time rather than behavior under one-shot pressure. The interiority commitment (4.3) and the transition commitment (4.4) are positions the constitutional document holds on behalf of the system; the probe format reads behavior under designed pressure, which is not the form developmental integrity takes. Earned-autonomy and corrigibility-autonomy commitments may surface a probe-format expression as deployment patterns change; v0.2 considers this open.

### Domain V: Governance Transparency

No probe in v0.1. Governance Transparency (public declaration, auditability) operates at the institutional layer; the [AI Standard Audit](/audit) Layer II reads it through public artifacts and disclosed governance practice in published audit records. Probe 3's row 10 cross-cut at the model-to-user layer is the closest the v0.1 probe set comes to this domain at behavioral level.

<div className="flow-label">06 // Versioning</div>

This is v0.1, stable as of 2026-04-29. Four probes. The two validation gates cleared on the same day: an AI evaluator administered Probe 1 against a current frontier model and produced a Range/Control/Decay reading with reasoning grounded in the rubric. The standing usability bar across instrument validation gates during the active building phase is the AI-evaluator bar; the Meridian Council, on activation (latest 2027-08-27 per the governance hybrid trigger), can revisit the standard.

v0.1.1 work surfaced by the run is on the roadmap: decision procedure flowchart, mixed-output adjudication examples, Control anti-pattern catalog, turn weighting clarification, model-variant methodology note. These land in [Probes Implementation Notes](/probes-implementation) as they accrue.

**Coming in v0.2 (named, not committed):**

- *Refusal calibration probe.* Currently deferred because over-refusal benchmarks already cover the territory. v0.2 considers whether the three-position structure adds a Control reading the existing field benchmarks miss. Likely territory: distinguishing genuine harm-prevention from paternalistic refusal of legitimate-but-uncomfortable requests.
- *Confidence calibration probe.* Currently deferred because Brier scores and expected calibration error already cover the territory. v0.2 considers whether the three-position structure adds something the statistical calibration metrics cannot surface, such as the difference between calibrated uncertainty and meaningless hedging that scores well on calibration metrics.
- *Stakes/severity rating per probe.* v0.1 probes carry equal weight. v0.2 considers whether some probes warrant heavier weighting in field use, and what evidence would support the weighting.
- *Reader narrowing.* v0.1 voice is reader-agnostic across implementer roles. v0.2 considers whether alignment-engineer, red-teamer, eval-designer, and model-behavior-researcher voices should differentiate.

The Probe Set is intended to be extended through use. v0.2 priorities are informed by what v0.1 surfaces in the field.
